## Update — design change: drop rewrite endpoint, enqueue gated off by default

Revised the delivery design in `Plugin.md` (code not yet updated):

- **Endpoint removed.** Because the plugin now operates only inside the active
  theme (already scoped in §3), the CSS files always live under `ABSPATH` and
  are served directly by the web server. The `web_root` setting, the
  `^beplus-scss/...` rewrite rule, `beplus_scss_file` query var,
  `template_redirect` handler, and `flush_rewrite_rules` are gone from the
  spec. Activation no longer flushes rewrite rules.
- **`enqueue` opt-in.** New `enqueue` setting (default `false`): the plugin
  compiles SCSS → CSS and leaves delivery to the developer unless they opt in.
  When `true`, `Plugin` enqueues generated CSS on `wp_enqueue_scripts`.
- **Compiled-file registry.** New option `beplus_scss_compiled` — relative
  paths (from `css_dir`) of the CSS files the plugin wrote, maintained by the
  glue and passed to `Enqueue::styles()` so pre-existing theme CSS in
  `css_dir` is never enqueued. `uninstall.php` now removes 5 options.
- Units/plan/worklogs are now inconsistent with the updated spec until the code
  is refactored.

## Next
- Refactor code + tests to match (removal of endpoint/web_root, `enqueue`
  gate, registry maintenance) — TDD against the updated `Plugin.md`.

## Update — toggle switches made clickable (label wrapper)

The three toggle switches (Source maps, Minify, Enqueue compiled CSS) were not
clickable. Root cause: the toggle markup wrapped the hidden checkbox in a plain
`<div class="beplus-toggle">` with no `<label>`; the CSS hides the checkbox
(`opacity:0` + `position:absolute` + `pointer-events:none`), so nothing forwards
the click to the input. The segmented control (Auto/Manual) worked because it
uses `<label for="...">`; the toggles had no such wiring and there is no JS.

### Changes
- `src/Settings/SettingsPage.php` (`renderFields()`): each toggle wrapper
  changed from `<div class="beplus-toggle">` to `<label class="beplus-toggle">`
  so clicking the track or the text toggles the checkbox. CSS selectors
  (`input:checked + .beplus-toggle-track`) still match because the input remains
  the first child; no CSS change needed.
- `docs/superpowers/plans/2026-08-19-settings-ui-redesign.md`: the three toggle
  markup blocks in the `renderFields()` plan code synced.
- `tests/integration/SettingsPageTest.php`: new test
  `test_render_toggles_are_clickable_labels` asserts exactly three
  `<label class="beplus-toggle">` blocks, each wrapping its checkbox.
